## 1. 项目是什么

Agent 账号管理器是一个**纯本地**的 macOS 桌面应用，用来管理 WorkBuddy 与 TRAE（国内版）的多个账号档案，并提供三件事：

1. **账号台账**：记录账号名称、脱敏手机号、套餐、备注、登录核对状态。
2. **快速进入账号**：TRAE 使用官方 `--user-data-dir` 启动账号专属实例；WorkBuddy 走官方人工退出/登录流程。
3. **积分与消耗台账**：手动录入积分余额，自动从 TRAE 本地日志采集任务与单任务积分消耗，计算「录入余额 − 之后的任务消耗」的预计余额。

### 1.1 核心设计原则

| 原则 | 具体表现 |
|---|---|
| 不保存敏感凭据 | 不保存密码、Token、Cookie；数据库只存脱敏手机号与手机号摘要 |
| 不改官方私有文件 | 不复制、不篡改 WorkBuddy / TRAE 的认证文件与配置 |
| 只使用官方能力 | TRAE 仅使用官方支持的 `--user-data-dir`；WorkBuddy 仅打开官方应用 |
| 区分「已启动」与「已登录」 | 打开客户端不等于登录目标账号，未验证时统一显示「等待核对」 |
| 不伪造数据 | 积分未知显示「未知」/「未记录」；任务消耗采集不到显示「未采集」，绝不写 0 |
| 平台差异显式呈现 | WorkBuddy 的运行状态只代表客户端在运行，不代表某个账号已登录 |

### 1.2 平台能力对照

| 能力 | WorkBuddy | TRAE（Trae CN） |
|---|---|---|
| 官方应用 | `WorkBuddy AI.app` | `Trae CN.app` |
| Bundle ID | `com.workbuddy.workbuddy-ai` | `cn.trae.app` |
| 启动方式 | 打开唯一客户端实例 | 通过内置 `trae-cn` 启动独立实例 |
| 账号隔离 | 不支持，同一时刻只能登录一个账号 | 支持，每个账号一个 `--user-data-dir` |
| 自动切换 | 不支持，必须人工退出并登录 | 可启动对应实例；首次仍需人工登录 |
| 身份技术验证 | 无官方手段 | 尝试 `traecli login status`（本机通常不可用） |
| 运行状态识别 | 仅平台级（客户端是否在运行） | 按账号实例区分 |
| 任务/积分消耗采集 | 不采集 | 从本地运行日志采集 |
| 积分余额 | 手动录入 | 手动录入 + 任务消耗推算 |

> 平台能力结论来自项目前期的平台能力核验。WorkBuddy 没有官方 CLI 或自动切换 API；TRAE 的独立实例能力继承自 VS Code 内核。

## 2. 快速上手

首次使用按以下顺序操作即可完成闭环：

1. **新增账号**：工具栏「+」或快捷键 `⌥⌘N`，选择平台，填写名称（手机号可留空）。
2. **启动并核对登录**：
   - TRAE：详情页「打开此账号」→「启动并核对登录…」，在打开的独立窗口中登录，再回来点「我已核对并登录」。
   - WorkBuddy：详情页「启动并核对登录」，在官方客户端退出当前账号并登录目标账号，再点「我已核对并登录」。
3. **录入积分**：在官方界面看到剩余积分后，点「录入积分」，填写数值与观测时间。
4. **查看任务消耗**：TRAE 账号在本应用启动的实例里执行任务后，详情页「任务消耗（日志）」会自动出现任务与消耗；每 5 秒刷新一次。
5. **定期备份**：设置（`⌘,`）→「备份到文件夹…」，把 `.sqlite` 备份放到安全位置。

## 3. 安装、构建与启动

### 3.1 环境要求

- macOS 14 或更高版本。
- Xcode（完整安装）或可用的 Swift 5.10+ 工具链。工程使用 Swift Package Manager，`Package.swift` 的 tools 版本为 5.10。
- 若 SwiftPM 清单链接失败，请安装完整 Xcode；打包脚本依赖 `swift build`。

### 3.2 常用命令

在项目根目录执行：

```bash
cd AgentAccountManager

swift build                 # Debug 构建
swift test                  # 运行全部单元测试（当前 177 项）
swift build -c release      # Release 构建
```

运行测试的实测结果（2026-10-31）：

```text
Executed 177 tests, with 0 failures
```

### 3.3 打包为 .app

```bash
./package.sh                # 生成 dist/AgentAccountManager.app
./package.sh --install      # 安装到 /Applications（不可写时回退 ~/Applications）
```

打包脚本 [package.sh](../package.sh) 的行为：

1. `swift build -c release`。
2. 清理并重建 `dist/AgentAccountManager.app`。
3. 复制可执行文件与 `assets/AppIcon.icns`。
4. 写入 `Info.plist`（应用名「Agent 账号管理器」、Bundle ID `com.agentaccountmanager.app`、版本 `0.1.0 (1)`、最低系统 14.0）。
5. 尝试 ad-hoc 签名（先签 Widget 扩展、再签外层 App，失败时跳过）。
6. `--install` 时：
   - 优先安装到 `/Applications`，不可写则安装到 `~/Applications`；
   - 若检测到目标应用正在运行，会中止并提示先退出；
   - 重新注册 LaunchServices；
   - **注销并删除 `dist` 下的副本**，避免 Spotlight 出现两个同名应用；
   - 刷新 Dock 与图标服务。

> 重要：`--install` 成功后会删除 `dist/AgentAccountManager.app`。如果还需要一份可拷贝的产物，请再执行一次不带参数的 `./package.sh`。

### 3.4 首次启动与 Gatekeeper

应用使用 ad-hoc 签名，未做 Developer ID 公证。若系统拦截：

- 在 Finder 中右键应用 →「打开」→ 再次确认；或
- 对直接运行 `dist` 副本的场景执行：

```bash
xattr -dr com.apple.quarantine "/path/to/AgentAccountManager.app"
```

通过 `./package.sh --install` 安装时，脚本已自动移除隔离属性。

### 3.5 升级与卸载

**升级**：退出正在运行的应用 → 重新执行 `./package.sh --install`。

**卸载应用**：

```bash
# 若安装在 /Applications
rm -rf "/Applications/AgentAccountManager.app"
# 若安装在 ~/Applications
rm -rf "$HOME/Applications/AgentAccountManager.app"
```

卸载应用不会自动删除本地数据。彻底清理见 [11.6 清空数据](#116-清空数据)。

## 4. 界面导览

主窗口默认 `1120 × 760`，最小 `960 × 620`，结构为「侧边栏 + 详情区」。

### 4.1 侧边栏

- **平台筛选**：下拉菜单选择 `TRAE` / `WorkBuddy` / `全部`，显示对应数量；未来新增平台可直接扩展。
- **显示范围**：`全部` / `运行中`，只是对现有账号列表的视图筛选，不会复制或修改数据。
- **排序**：右侧箭头菜单可切换「最近使用 / 账号名称 / 收藏优先」。
- **搜索框**：匹配账号名称、脱敏手机号、套餐、备注；按 `⌘F` 直接聚焦，搜索范围与当前平台筛选叠加。
- **最近项目**：侧边栏底部固定区域展示跨账号最近的 TRAE 项目（近 7 天最多 15 条），默认露出 5 行，可滚动查看，点击即在对应账号实例中打开。
- **账号列表**：默认按「最近使用时间」倒序；从未使用的账号排在后面，再按平台与创建时间排序。
- **收藏**：行内星标或 `⌘D` 切换，收藏会影响排序（收藏优先）。

列表行信息（分三行展示，避免挤在一行）：

1. 平台徽章 + 账号名称 + 星标；
2. 脱敏手机号 · 套餐；
3. 积分或预计积分 + 状态标签。

列表状态标签含义：

| 标签 | 含义 |
|---|---|
| 待核对 | 已发起切换，但尚未在官方界面核对 |
| 已确认 | 用户此前人工核对并确认过登录 |
| 已验证 | 最近一次切换通过官方 CLI 验证到身份 |
| 已退出 | 历史状态值，当前版本没有单独的「标记退出」入口 |
| 积分过期 | 最近一条积分记录已超过 12 小时 |
| 余额需校准 | 采集到的任务消耗已超过记录的余额（预计值为负） |
| 采集异常 | 任务日志中出现了无法解析的事件行，格式可能已变化 |
| 确认冲突 | 多个 WorkBuddy 账号同时标记为「已确认」，但一个客户端只能登录一个账号 |
| 运行中 | 该账号的 TRAE 独立实例有进程在运行（按 `--user-data-dir` 区分） |
| 客户端已打开 | WorkBuddy 客户端在运行（仅平台级，不代表登录的是该账号） |

**登录状态、实例运行状态、积分状态与采集状态是四个维度**，界面分别展示，不会合并成一个「异常」标签；运行中不代表登录身份已验证。

### 4.2 详情区

标题区保留名称、平台、脱敏手机号、登录状态标签、运行状态标签、收藏星标与 `⋯` 菜单（编辑 / 删除）。标题区下方依次是提示区与核心操作，正文按 **概览 / 积分与任务 / 历史记录** 三个分区展示：

1. **标题区**：账号身份与两类状态；星标可直接收藏。
2. **待处理提示区**：仅当状态为「等待核对」时出现，提供「我已核对并登录」与「重新走切换流程」。
3. **WorkBuddy 确认冲突提示**：出现冲突时展示，并提供「把其他 WorkBuddy 账号标记为未核对」。
4. **安装异常提示**：官方应用未安装或 TRAE 内置 CLI 不可用时出现。
5. **核心操作区**：
   - TRAE 主按钮：有上次项目时显示「打开「项目名」」，否则显示「打开此账号」；**点击即完成打开**（实例已在运行则直接激活，否则以独立目录启动并恢复上次项目）。
   - 主按钮右侧菜单：启动并核对登录…、在某个已打开的项目中重新打开、运行中窗口列表、启动空白窗口。
   - WorkBuddy：主按钮「启动并核对登录」；
   - 次按钮「录入积分」。
6. **概览**：
   - 账号信息卡：平台、套餐、备注、最近切换、档案更新；TRAE 额外展示独立配置目录状态、运行中的项目、最近 3 天打开的项目。
7. **积分与任务**：
   - 积分余额卡：当前/预计积分、最近实际录入、余额基准时间、基准后已采集消耗、未采集消耗任务数、总额度、积分类型、数据来源、观测时间，并提供「重新录入实际余额」快捷入口；
   - 任务采集诊断卡：最近扫描、最近成功解析、本次读取轮次/文件数、新增事件数、未采集消耗、疑似格式变化、读取失败，并提供「立即采集」；
   - 任务消耗卡：任务名、时间、Agent、模型、状态、单任务积分；只有 TRAE 账号会产生数据。
8. **历史记录**：
   - 积分变化卡：趋势线与每次观测值/差值，可展开全部或加载更早记录；
   - 切换记录卡：每次切换的状态迁移、结果、失败原因。

### 4.3 设置窗口

快捷键 `⌘,` 打开，包含：

- 数据位置（数据库文件、Finder 定位、打开数据目录、TRAE 独立配置目录路径）；
- 备份与恢复（备份到文件夹、从备份恢复、导出 CSV、清空所有本地数据）；
- 诊断信息（账号/积分/切换/任务记录条数、应用版本、两平台安装状态）；
- 安全与诚实约束说明。

### 4.4 自动刷新机制

- 应用每 **5 秒**刷新一次客户端运行状态，并增量采集 TRAE 任务日志。
- 应用重新获得焦点（`didBecomeActive`）时立即刷新运行状态、最近项目并采集一次。
- 详情页在账号档案更新、任务采集版本变化、应用激活时重新加载数据。
- 最近项目面板只在「全部」范围、无搜索、且非纯 WorkBuddy 视图时展示，近 7 天最多 15 条，默认露出 5 行可滚动。
- 桌面快速切换小部件每次显示、点击刷新按钮或通过快捷键切换时，都会刷新运行状态与最近项目。

### 4.5 快捷键

| 快捷键 | 行为 |
|---|---|
| `⌘F` | 聚焦搜索框 |
| `⌘↩` | 打开所选账号（优先恢复上次项目，已运行则激活） |
| `⌘⇧↩` | 为所选账号启动空白窗口 |
| `⌘D` | 收藏 / 取消收藏所选账号 |
| `⌘R` | 立即采集 TRAE 任务日志 |
| `⌥⌘N` | 新增账号 |
| `⌥⌘K` | 显示 / 隐藏桌面快速切换小部件 |
| `⌘,` | 打开设置 |

键盘方向键可在账号列表中切换选中项。

### 4.6 桌面快速切换小部件

小部件是一个无边框悬浮面板，用来把「打开账号」和「打开最近项目」从主窗口里解放出来，适合在 TRAE 全屏或其他应用前快速切换。

| 入口 | 行为 |
|---|---|
| 主窗口 / 工作台工具栏「快速切换」 | 显示或隐藏小部件 |
| `⌥⌘K` | 应用内快捷键显示或隐藏小部件 |
| 小部件右上角 `×` / `Esc` | 关闭小部件 |

面板内容：

- **顶部摘要**：账号数、运行中实例数、最近项目数；绿点只在存在运行中实例时出现。
- **自适应高度**：列表少时面板自动收缩，最多展示 8 行，其余滚动。
- **置顶按钮**：默认置顶并跟随所有桌面空间，浮在其他应用窗口上方；取消置顶后回到普通窗口层级。
- **账号页签**：按「收藏 → 运行中的 TRAE 实例 → 最近使用」排序。点击整行即恢复该账号上次项目并打开/激活实例；右键菜单可启动空白窗口、收藏、在账号管理器中查看。
- **项目页签**：近 7 天最多 15 个最近项目，点击即在所属账号的独立实例中打开。
- **底部**：回到账号管理器、刷新运行状态与最近项目，并提示 `⌥⌘K`。

行为约定：

- 小部件在点击时不主动抢占当前应用焦点（non-activating panel），点击账号或项目才执行对应操作。
- 小部件的位置与可见状态会记住；下次启动时若上次未关闭，会自动恢复。
- 绿点只表示「实例/客户端在运行」，不表示登录身份已验证；登录核对状态仍在账号详情页处理。
- WorkBuddy 仍只能唤醒唯一客户端，小部件无法直接切换其登录账号。
- 同时提供一个 macOS 通知中心 WidgetKit 小组件（快速切换）：展示账号与最近项目，点击通过深链回到主应用打开对应账号或项目。它只读主应用写入的快照文件，不能直接启动实例；主应用长时间未运行时快照会标注「数据已过期」。

## 5. 账号管理

### 5.1 新增账号

入口：工具栏「+」、空状态按钮「新增账号」、快捷键 `⌥⌘N`。

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| 平台 | 是 | WorkBuddy 或 TRAE；创建后不可修改 |
| 账号名称 | 是 | 用于列表与识别，可重复 |
| 手机号 | 否 | 完整号码只写入 macOS 钥匙串；数据库保存脱敏值与 SHA-256 摘要 |
| 套餐类型 | 否 | 如「Pro」「会员」等自由文本 |
| 备注 | 否 | 自由文本，列表中悬停可查看 |

手机号处理：

- 数据库只保存形如 `138****1234` 的脱敏值。
- 完整号码写入钥匙串（Service：`com.agentaccountmanager`，Account：`phone:<账号UUID>`）。
- 同时保存手机号的 SHA-256 摘要，用于查重。
- 输入已存在的手机号时，表单会提示「该手机号已用于：…」，但**不禁止保存**，因为同一手机号可能对应不同平台账号。
- 手机号留空不影响使用。

创建成功后的提示：

- 写入钥匙串成功：「账号已创建，完整手机号已存入 macOS 钥匙串」；
- 写入失败：「账号已创建，但完整手机号未能写入钥匙串」（账号仍会创建）。

### 5.2 编辑账号

入口：标题区 `⋯` →「编辑账号」。

- 可修改：名称、手机号、套餐、备注。
- 平台不可修改。
- 手机号留空表示**不修改**；填写新号码会覆盖原值并更新钥匙串。
- 套餐与备注留空表示**清空**对应字段（表单提交的是完整快照）。
- 编辑保存后提示「账号信息已保存」。

### 5.3 删除账号

入口：标题区 `⋯` →「删除账号…」。

确认框会列出将删除的数据影响：

- 账号档案 1 条；
- 积分记录 N 条；
- 切换记录 N 条；
- 任务记录 N 条；
- 若为 TRAE 账号且独立配置目录存在：删除该目录（含该账号本地登录数据）。

确认按钮为「删除并清理本地数据」。删除操作会：

1. 删除 TRAE 独立配置目录（仅 TRAE）；
2. 删除钥匙串中的完整手机号；
3. 删除账号行，并通过外键级联删除积分快照、切换日志、任务记录、项目打开记录；
4. 清空当前选中项；
5. 刷新列表。

> 删除只影响本机台账与本地隔离数据，不会注销或删除官方平台上的账号。

### 5.4 选中状态记忆

应用会记住上次查看的账号（`UserDefaults` 键 `lastSelectedAccountId`），下次启动自动回到该账号详情；若该账号已删除则回到空状态。

## 6. TRAE：独立实例与项目打开

### 6.1 隔离原理

- 每个 TRAE 账号分配一个独立配置目录：

```text
~/Library/Application Support/AgentAccountManager/TraeUserData/<账号 UUID>/
```

- 启动命令为 TRAE 官方内置 CLI：

```text
/Applications/Trae CN.app/Contents/Resources/app/bin/trae-cn --user-data-dir <该账号目录> [项目路径]
```

- 首次切换时创建目录；首次需要在该窗口中登录目标账号；之后 TRAE 会把会话持久化到该目录，再次启动可复用。
- 应用不会复制或修改 TRAE 的认证文件，只使用官方 `--user-data-dir` 参数。

### 6.2 「打开账号」主操作

TRAE 详情页主按钮会根据是否有上次项目显示「打开「项目名」」或「打开此账号」。**点击主按钮即完成打开**，右侧菜单提供低频选项：

| 操作 | 出现条件 | 行为 |
|---|---|---|
| 点击主按钮 / `⌘↩` | 始终 | 有上次项目则恢复该项目，否则打开空白窗口；实例已运行且窗口存在时直接激活 |
| 启动并核对登录… | 始终 | 打开三步切换流程（首次使用、登录状态不明确时使用） |
| 在「项目名」中重新打开 | 存在上次项目 | 以该账号独立目录启动并打开指定项目 |
| 运行中的项目名称 | 实例运行且检测到已打开窗口 | 直接激活对应窗口；不会新起进程 |
| 启动空白窗口 / `⌘⇧↩` | 始终 | 实例已运行且有窗口时激活；否则以无项目参数启动独立实例 |

设计意图：

- 已经正常使用的账号不必每次都走完整三步向导，一次点击即可回到上次项目。
- 重复执行 `trae-cn --user-data-dir` 会短暂启动一个转发进程，表现为 Dock 图标「开一下又关掉」。因此**实例已运行且目标窗口已打开时只做激活**。
- 若目标项目尚未在该实例中打开，则仍通过 CLI 启动一次，让 TRAE 打开该项目。
- 若实例进程存在但所有窗口都已关闭，激活会失败，此时会重新启动实例。
- 首次使用、会话状态不明确或需要重新核对时，仍通过「启动并核对登录…」完成人工核对，不跳过登录验证。

### 6.3 运行状态识别

应用只查询 TRAE 主进程：

1. 通过 `NSWorkspace` 找到 Bundle ID 为 `cn.trae.app` 的进程 PID；
2. 执行 `ps -p <pid,...> -o pid=,args=`；
3. 解析命令行中的 `--user-data-dir <root>/<UUID>`，同时兼容 `--user-data-dir=<路径>` 写法；
4. 只认本应用根目录 `.../AgentAccountManager/TraeUserData/` 下的 UUID，默认配置目录（如 `Trae CN`）会被忽略。

因此「实例运行中」是按账号精确区分的，而不是「TRAE 在运行」。

### 6.4 项目记录

TRAE 账号会展示两类项目信息：

**运行中的项目**

- 来源：该账号隔离目录下 `User/globalStorage/storage.json` 的 `lastActiveWindow` 与 `openedWindows`。
- 缺少窗口记录时，回退到 `User/workspaceStorage/*/workspace.json` 中最近修改的一个项目。
- 只展示仍然存在的目录；点击即激活该窗口。

**最近 3 天打开**

- 合并两类来源：
  1. 本应用精确记录的打开事件（含打开次数）；
  2. TRAE 隔离目录中 `workspaceStorage/<hash>/workspace.json` 的修改时间（近似最近活动）。
- 仅展示最近 3 天、仍然存在的目录，最多 20 个。
- 在 TRAE 内直接打开的项目只能按文件修改时间近似；启用本功能之前的历史无法追溯。
- 应用启动时会清理 90 天前的项目打开记录，控制表体积。

### 6.5 首次使用 TRAE 的建议步骤

1. 确认 `Trae CN.app` 安装在 `/Applications`（或系统能通过 Bundle ID 找到）。
2. 新增 TRAE 账号。
3. 点「打开此账号」→ 菜单里的「启动并核对登录…」（首次没有记录，主按钮会打开空白窗口）。
4. 在打开的 TRAE 窗口中登录目标账号。
5. 回到本应用，点「我已核对并登录」。
6. 之后每次使用同一账号时，应用会复用该独立目录与上次项目。

## 7. WorkBuddy：单实例人工切换

WorkBuddy 只有一个客户端实例，没有官方 CLI、没有账号隔离能力，同一时刻只能登录一个账号。因此：

- 本应用**无法自动切换** WorkBuddy 账号；
- 「启动并核对登录」只会打开 WorkBuddy 客户端，并给出人工步骤；
- 运行状态标签「客户端已打开」只代表进程存在，**不代表当前登录的是列表中的这个账号**。

标准流程：

1. 在详情页点「启动并核对登录」；
2. 在 WorkBuddy 中退出当前账号；
3. 用目标账号完成登录；
4. 回到本应用点「我已核对并登录」。

### 7.1 确认冲突

如果多个 WorkBuddy 账号都被标记为「已确认」，这些确认不可能同时成立。应用会：

- 在列表与详情显示「确认冲突」标签；
- 在详情页提示「WorkBuddy 同一客户端同一时刻只能登录一个账号」；
- 提供「把其他 WorkBuddy 账号标记为未核对」按钮，由用户主动清理，不做静默改写。

## 8. 切换流程与登录状态语义

### 8.1 三步流程

切换 Sheet 固定为三步：

1. **确认目标**：展示名称、手机号、套餐、当前状态；TRAE 额外展示上次项目；说明平台差异与安装问题。
2. **执行切换**：后台调用 `SwitchService`，界面显示进度。
3. **核对结果**：展示结论、是否已启动、是否已验证身份、需要用户完成的步骤、失败建议。

结果类型：

| 结果 | 标签 | 含义 |
|---|---|---|
| success | 已启动 | 官方手段验证到身份（当前仅 TRAE + `traecli` 成功时） |
| unconfirmed | 等待核对 | 客户端已启动，但身份未验证 |
| failed | 未完成 | 未启动或启动失败 |

底部按钮：

- 已验证：`完成`；
- 未验证但已启动：`稍后再说` / `我已核对并登录`；
- 失败：`关闭` / `重试`。

### 8.2 登录状态

| 状态 | 展示 | 产生方式 |
|---|---|---|
| `unknown` | 状态未记录 | 新账号默认 |
| `loggedOut` | 已退出 | 兼容历史数据；当前界面无设置入口 |
| `pendingConfirmation` | 等待核对 | 已启动客户端但未核对 |
| `userConfirmed` | 已人工确认 | 用户点击「我已核对并登录」 |
| `verified` | 已验证身份 | TRAE 切换时 `traecli login status` 成功返回 |

### 8.3 状态更新规则

切换后状态由证据决定：

- **未启动或失败**：保持原状态，不制造任何「成功」痕迹。
- **本次官方验证成功**：写「已验证身份」。
- **上次是「已验证」但本次未验证**：降级为「已人工确认」（验证只对当时那一刻有效）。
- **此前已人工确认**：
  - WorkBuddy：保留确认结果；
  - TRAE：有持久化会话则保留，没有会话则回到「等待核对」。
- **其余情况**：置为「等待核对」。

补充规则：

- 只有**实际启动过客户端**，才更新账号的「最近切换」时间。
- TRAE 实际启动后，会把该账号上次打开的项目记入项目打开记录。
- 每次切换（包括失败）都会写入切换日志；失败原因会脱敏后保存。
- 「已验证身份」只代表最近一次验证当时的结果，不代表此后一直有效。

> `traecli` 与 TRAE 桌面端是否共享登录态仍是未验证风险（技术调研报告 R2）。当前实现把 CLI 的成功返回视为技术验证，但本机通常没有 `traecli`，因此大多数 TRAE 切换会停在「等待核对」。

## 9. 积分余额与任务消耗

### 9.1 手动录入积分

目前**没有接入官方积分查询 API**，积分只能手动录入。入口：详情页「录入积分」。

字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 剩余积分 | 是 | 非负整数；必须与 Token、人民币余额等单位区分 |
| 总额度 | 否 | 未知可留空 |
| 积分类型 | 否 | 常用快捷项：WorkBuddy「积分」；TRAE「会员积分」「奖励积分」 |
| 观测时间 | 是 | 默认现在，可回填此前看到积分的时刻，不能晚于当前时间 |

保存行为：

- 写入一条成功快照（来源「手动录入」）；
- 更新账号的当前积分、总额度、积分类型、观测时间、数据来源与状态；
- 总额度或积分类型留空时保留账号原值；
- 提示「积分已保存，之后的任务消耗会从这里实时扣减」。

### 9.2 预计余额的计算

```text
预计余额 = 最近一次成功录入的余额 − 该时刻之后采集到的任务消耗合计
```

规则：

- 基准取**最近一条成功快照**（按观测时间倒序）。
- 只统计 `createdAt > 基准时间` 的任务消耗。
- 基准之后的任务无论成功、失败还是中断，只要日志里采集到消耗就计入。
- 未采集到消耗的任务不计入扣减，单独显示「未采集消耗 N 个任务 · 暂未计入」。
- 没有任何成功录入时，不计算、不猜测，列表显示「未记录」。
- 重新录入最新余额会重置基准，此前已扣减的任务消耗自动不再计入，避免重复扣减。
- 若预计余额为负数，会提示「任务消耗已超过记录的余额，请录入实际余额重新校准」。

展示优先级：

- 有预计余额 → 展示 `estimatedCredits`；若基准后有扣减，前缀改为「预计积分」；
- 否则退回账号的最近录入值；
- 查询失败状态下显示「积分 上次查询失败」，但不会把余额清零。

### 9.3 数据新鲜度

- 积分记录默认 **12 小时**后视为过期。
- 列表显示「积分过期」标签；详情页副标题变为「记录已超过 12 小时，可能已变化」。
- 过期判断是展示层计算，不修改数据库中的积分值。

### 9.4 TRAE 任务与单任务消耗

**采集范围**

- 仅 TRAE 账号。
- 只读取本应用创建的隔离目录：

```text
.../TraeUserData/<账号 UUID>/logs/<yyyyMMddTHHmmss>/window*/renderer.log
```

- 每次最多补采最近 **2 轮**日志、且不早于 **7 天**，每轮最多 8 个窗口文件；同一 `messageId` 重复出现会由数据库去重，不会重复计数。
- 每个日志文件按字节偏移增量读取；首次读取最多回看最近 16 MB。
- 偏移量持久化在 UserDefaults 中（只保留仍存在的日志文件，最多 300 条），应用重启后继续从上次位置读取，不会重复解析。
- 文件被截断或轮转时从头读取；只推进到最后一个完整换行，未写完的半行会在下次扫描重新读取，不会丢失。

**解析内容**

通过 `messageId` 关联三类日志行：

| 日志事件 | 提取内容 |
|---|---|
| `[MetadataHandler] received metadata` | 会话 ID、messageId、用户输入首行摘要、模型名、Agent 名、状态 |
| `cn_session_usage_tail` | 单轮任务积分消耗 `usage_summary` |
| `[DoneHandler] Stream done event received` / `[stream-diagnostics][done] done received` | 任务结束状态 |

**写入规则**

- 同一 `messageId` 去重；重复日志只写入实际变化的字段，后续非空值可以补齐或更新（例如状态从「进行中」变为「已完成」、补上积分消耗）。
- 任务名只保存用户输入首行，最长 60 字符；不保存完整对话。
- 状态映射：`in_progress/running/pending/active` → 进行中；`completed/success/done/finished` → 已完成；`failed/error` → 失败；`interrupted/cancelled/canceled/aborted` → 已中断；其余为未知。
- 积分未采集到时为 `nil`，界面显示「未采集」，不写 0。
- 任务记录随账号删除级联清理。

**刷新节奏**

- 每 5 秒增量采集一次；应用获得焦点时立即采集。
- 只有真正写入变化时才刷新界面，避免无意义重绘。

**采集诊断**

详情页「积分与任务 → 任务采集诊断」展示：最近扫描时间、最近成功解析时间、本次读取的轮次/文件数、新增事件数、未采集消耗任务数、疑似格式变化行数与读取失败数，并可「立即采集」。

- 「本次没有新任务」是正常状态，不会被判定为解析故障。
- 只有出现「已识别的标记但字段无法解析」的行，才记为疑似格式变化，提示日志格式可能已更新。
- 诊断中的时间只代表本地日志的读取事实，不代表官方账户状态。

> 任务消耗来自 TRAE 本地日志，是**按轮次累加的推断值**，不是官方账户余额；日志格式属于非公开格式，字段缺失时会降级或显示「未采集」。

## 11. 数据、安全与备份

### 11.1 数据位置

| 数据 | 路径 / 位置 |
|---|---|
| SQLite 数据库 | `~/Library/Application Support/AgentAccountManager/AgentAccountManager.sqlite` |
| SQLite 边车文件 | 同目录下的 `-wal` / `-shm` |
| TRAE 独立配置目录 | `~/Library/Application Support/AgentAccountManager/TraeUserData/<账号 UUID>/` |
| 完整手机号 | macOS 钥匙串，Service `com.agentaccountmanager`，Account `phone:<账号 UUID>` |
| 上次选中账号 | `UserDefaults` 键 `lastSelectedAccountId` |
| 运行日志 | `os.log`，Subsystem `com.agentaccountmanager` |

### 11.2 数据库结构（schema v7）

| 表 | 主键 | 内容 | 关联 |
|---|---|---|---|
| `accounts` | `id` | 账号档案、登录状态、积分快照字段、最近使用时间、TRAE 目录 | — |
| `credit_snapshots` | `id` | 每次录入/查询失败的积分快照 | `accountId` → `accounts.id`，级联删除 |
| `switch_logs` | `id` | 每次切换的状态迁移、结果、失败原因 | `accountId` → `accounts.id`，级联删除 |
| `trae_tasks` | `id`（= messageId） | 任务元数据与单任务消耗 | `accountId` → `accounts.id`，级联删除 |
| `project_visits` | `id` | 项目路径、最近打开时间、打开次数 | `accountId` → `accounts.id`，级联删除；`(accountId, workspacePath)` 唯一 |

关键约束：

- 每次打开数据库都执行 `PRAGMA foreign_keys = ON`，确保级联删除生效。
- schema 版本通过 `PRAGMA user_version` 管理，当前支持 v1–v7。
- 迁移记录：v2 清理孤儿行；v3 重建 `accounts` 表（移除 `creditResetAt`、新增 `lastUsedAt`）；v4 用历史切换日志回填 `lastUsedAt`；v5 新增任务表；v6 新增项目打开记录；v7 新增项目与三工位表。

### 11.3 安全设计

| 数据 | 存储方式 |
|---|---|
| 账号名称、套餐、备注 | SQLite 明文（用户主动填写的非敏感信息） |
| 手机号（展示） | 脱敏值 `138****1234` |
| 手机号（完整） | 钥匙串，系统加密 |
| 手机号摘要 | SHA-256，用于查重 |
| 密码 / Token / Cookie | **不保存** |
| 运行日志 | 自动把 11 位连续数字替换为 `1**********` |
| TRAE 窗口/项目状态 | 只读取 `storage.json` / `workspace.json` 中的窗口与路径字段，不读取认证数据 |

应用明确不做：

- 不复制、不修改官方应用的私有认证文件；
- 不把「打开客户端」当成「登录成功」；
- 不把查询失败写成 0；
- 不在没有证据时显示「已验证」。

### 11.4 备份

入口：设置 →「备份到文件夹…」。

- 文件名：`AgentAccountManager-backup-yyyyMMdd-HHmmss.sqlite`。
- 内容：数据库中的账号档案、积分快照、切换日志、任务记录、项目打开记录。
- **不包含**：钥匙串中的完整手机号、TRAE 独立配置目录（登录态）。
- 写入后会立刻只读打开并执行 `PRAGMA integrity_check`，完整性校验不通过会直接报错，避免留下坏备份。

### 11.5 恢复

入口：设置 →「从备份恢复…」。

恢复流程：

1. 校验文件：能只读打开、`PRAGMA integrity_check` 通过、存在 `accounts` 表、schema 版本在支持范围内；
2. 自动把当前数据库备份到原目录，文件名为 `AgentAccountManager-pre-restore-yyyyMMdd-HHmmss.sqlite`；
3. 关闭连接、替换数据库文件、删除旧 WAL/SHM；
4. 复制失败时自动回滚到恢复前的数据；
5. 重新装配服务并清空选中项。

注意：

- 恢复会覆盖当前账号档案、积分历史与切换记录；
- 钥匙串中的完整手机号**不会被恢复**；如果备份来自另一台 Mac，或钥匙串已被清空，恢复后手机号只显示脱敏值，需要重新填写；
- TRAE 独立配置目录不会被恢复或删除，已有目录仍按原样存在。

### 11.6 导出与清空数据

**导出 CSV**：设置 →「导出 CSV…」，可选择数据类型（任务记录 / 积分记录）、账号（单个或全部）与时间范围（全部 / 最近 7 天 / 最近 30 天）。

- 任务字段：时间、任务摘要、状态、积分消耗、模型、Agent；未采集消耗导出为「未采集」而不是 0。
- 积分字段：时间、积分、总额度、来源、状态、说明。
- 字段按 CSV 规则转义，文件带 UTF-8 BOM，便于 Excel 正确显示中文。
- **不导出**手机号、Token、Cookie 或本地认证数据。

**清空全部数据**：设置 →「清空所有本地数据」→「清空并重置」。确认框会明确列出删除范围与保留范围。

会删除：

- SQLite 数据库文件与边车文件；
- 钥匙串中本应用写入的全部凭据；
- 当前选中账号记录。

**不会删除**：

- `TraeUserData` 下的 TRAE 独立配置目录（登录态仍在），确认框会显示当前目录数量；
- 官方平台上的任何账号；
- 已导出的备份与 CSV 文件。

如需彻底清理 TRAE 登录数据，请先逐个删除 TRAE 账号（删除账号会移除对应目录），或手动删除：

```bash
rm -rf "$HOME/Library/Application Support/AgentAccountManager/TraeUserData"
```

### 12.1 诊断信息

### 12.2 常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 首次打开被系统拦截 | ad-hoc 签名，未公证 | 右键「打开」，或移除 quarantine 属性 |
| 系统里出现两个同名应用图标 | 同一 Bundle ID 存在多份副本 | 退出应用，删除 `dist` 或其他副本，执行 `lsregister -u <副本路径>`，重新 `./package.sh --install` |
| 「启动并核对登录」按钮置灰 | 官方应用未安装，或 TRAE 内置 CLI 不可用 | 安装/重装完整版应用；设置页查看具体提示 |
| TRAE 提示「内置命令行不可用」 | `Trae CN.app/Contents/Resources/app/bin/trae-cn` 不存在或不可执行 | 使用完整安装包重装 TRAE |
| 首次切换后停在欢迎页 | 该账号还没有上次项目记录 | 正常现象；登录后打开项目，下次会自动沿用 |
| 点击项目没有反应 | 实例在运行，但目标项目未在该实例打开；或窗口已全部关闭 | 应用会回退到 CLI 启动；若仍失败，使用「启动空白窗口」 |
| TRAE 窗口已开但应用显示未运行 | 进程没有带本应用的 `--user-data-dir`，或命令行解析不匹配 | 确认是从本应用启动的实例；手动启动的默认实例不计入 |
| 列表显示「积分未记录」 | 还没有成功录入过余额 | 点击「录入积分」保存一次 |
| 任务消耗显示「未采集」 | 日志里没有该轮 usage 记录，或格式变化 | 等待任务结束；确认是从本应用启动的实例；不要用 0 代替 |
| 任务列表为空 | 账号未执行过任务，或任务发生在补采范围（最近 2 轮 / 7 天）之外 | 在 TRAE 内执行一次任务，5 秒后刷新；详情页「立即采集」查看诊断 |
| 详情页显示「本次没有新任务」 | 日志已读到末尾，没有新增事件 | 正常状态，不是解析故障 |
| 显示「疑似格式变化」 | 日志里出现带任务标记但字段不完整的行 | 打开诊断卡查看计数；多数情况下不影响已有任务记录 |
| 列表点「收藏」无变化 | 当前显示范围不是「收藏」 | 切到「收藏」筛选，或看行内星标是否点亮 |
| `⌘F` 无反应 | 焦点不在主窗口，或有模态框 | 关闭弹窗后重试；也可直接点搜索框 |
| 多个 WorkBuddy 显示「已确认」 | 多个账号都点了人工确认 | 以官方界面为准，使用「把其他 WorkBuddy 账号标记为未核对」 |
| 切换结果一直是「等待核对」 | 本机没有可用的 `traecli`，无法技术验证 | 正常；在官方界面核对后点「我已核对并登录」 |
| 恢复备份失败 | 选错文件、schema 版本不支持、复制失败 | 选择本应用生成的 `.sqlite`；查看错误提示；恢复前数据已自动备份 |
| 清空数据后 TRAE 仍是登录状态 | 清空不删除 `TraeUserData` | 先删除 TRAE 账号，或手动删除目录 |
| 启动提示「数据库不可用」 | 文件被占用、权限异常、恢复中断 | 重启应用；检查数据目录权限；从备份恢复 |

图标缓存仍残留时（仅在确认只有一个应用副本后执行）：

sudo killall iconservicesagent Finder Dock

## 13. 已知边界与限制

这些限制是当前版本的**明确设计边界**，不是未发现的问题：

1. **WorkBuddy 无法自动切换或验证身份**：只有单实例、无官方 CLI。应用只负责打开客户端和记录人工确认。
2. **TRAE 身份验证通常不可用**：`traecli` 可能不存在，且与桌面端登录态是否共享尚未验证。应用不会因此伪造「已验证」。
3. **没有官方积分查询**：当前只有手动录入；服务层保留了查询失败的处理逻辑，但界面未接入自动查询。
4. **任务消耗是日志推断值**：只覆盖本应用隔离目录下的 TRAE 日志；不是官方账单。
5. **任务采集范围有限**：每次最多补采最近 2 轮日志（7 天内），每轮最多 8 个文件，首次读取单文件最多回看 16 MB；更早的历史不会自动导入。
6. **采集偏移保存在本机偏好设置**：应用重启后会恢复上次读取位置；日志被轮转/截断时偏移归零并依赖 `messageId` 去重兜底。若日志被清空且任务未入库，仍可能缺失。
7. **最近项目是近似值**：本应用发起的打开是精确记录；在 TRAE 内直接打开的项目只按 `workspace.json` 修改时间推断。
8. **WorkBuddy 运行标签是平台级**：无法判断当前登录的是哪个账号。
9. **清空数据不删除 TRAE 登录目录**：见 11.6。
10. **编辑手机号留空不会清除**：留空表示「不修改」；当前没有单独清除手机号的入口。
11. **仅支持 WorkBuddy 与 TRAE 国内版**：没有国际化 TRAE 或其他 Agent 平台。
12. **ad-hoc 签名、无公证、无自动更新**：分发到其他 Mac 时可能需要手动放行。
13. **过期阈值固定为 12 小时**：没有设置项。
14. **以多窗口工作流为主**：已提供桌面快速切换小部件与 `⌥⌘K`，但仍没有菜单栏常驻图标、没有批量导入账号，也没有针对多窗口的专门支持；CSV 导出已支持任务与积分记录。
15. **「上次确认时间较早」未实现**：账号模型没有记录人工确认时间，界面不会对久未核对的状态做时间衰减提示（状态本身也不会被自动改写）。
16. **采集诊断只保留在本次运行内**：诊断数据不落库，重启后从当前扫描重新累计。

## 14. 后续优化建议

以下建议按「收益 / 风险」排序，均可直接落到现有结构。

### 14.1 数据生命周期（优先级：高）

1. **清空数据时提供可选删除 TRAE 目录**（未完成）
   - 现状：`BackupRestore.deleteAllData()` 只删除数据库与钥匙串，`TraeUserData` 残留登录态；确认框已明确说明删除/保留范围并显示目录数量。
   - 建议：设置页增加「同时删除 TRAE 独立配置目录」复选框，或在清空流程中提供独立入口。
2. **积分/任务导出 CSV**（已完成）
   - 设置 →「导出 CSV…」：可选数据类型、账号、时间范围；不包含手机号等敏感字段。
3. **数据保留策略可配置**（未完成）
   - 现状：项目记录固定 90 天，任务与积分永久保留。
   - 建议：设置页增加保留天数，避免数据库无限增长。

### 14.2 采集可靠性（优先级：高）

1. **持久化日志读取偏移**（已完成）
   - `TraeTaskScanner` 把每个文件的偏移写入 `UserDefaults`，启动时恢复；仍以 `messageId` 去重兜底。
2. **按轮次回溯采集**（已完成）
   - 每次扫描补采最近 2 轮（7 天内），每轮最多 8 个文件；更早的轮次不导入。
3. **日志格式变化监测**（已完成）
   - 诊断卡展示最近扫描、最近成功解析、新增事件、疑似格式变化与读取失败计数。

### 14.3 安全与完整性（优先级：中高）

1. **手机号摘要加盐或改为 HMAC**（未完成）
   - 现状：SHA-256 对 11 位手机号可被穷举。
   - 建议：使用应用级随机盐或 Keychain 中的密钥做 HMAC；迁移时保留旧值匹配逻辑。
2. **钥匙串写入失败可见化**（未完成）
   - 现状：创建账号时如果钥匙串写入失败只给 toast；编辑时失败被忽略。
   - 建议：记录状态并在账号详情展示「完整手机号未保存」，提供重试。
3. **备份完整性校验**（基础版已完成）
   - 现状：备份写入后立即执行 `PRAGMA integrity_check` 与表结构校验；恢复前自动保全当前数据库。备份文件本身仍未生成独立摘要。
   - 建议：进一步生成 SHA-256 校验文件，恢复时比对。

### 14.4 性能与响应（优先级：中）

1. **运行状态改为事件驱动**
   - 现状：每 5 秒调用一次 `NSWorkspace` + `ps`。
   - 建议：监听应用启动/退出通知，日志采集使用 FSEvents 或 DispatchSource 文件监听，降低轮询成本。
2. **详情页查询批量化**
   - 现状：刷新时分别查询积分、任务、切换记录条数与首屏。
   - 建议：合并为一次多结果查询或缓存统计值。

### 14.5 产品能力（优先级：中）

1. **官方额度查询（阶段 F）**
   - 前提：平台提供可验证的官方接口/CLI。
   - 要求：保留「查询失败不清零」语义，来源标记为官方接口。
2. **菜单栏快速切换**
   - 适用：高频切换 TRAE 账号。
   - 注意：WorkBuddy 仍只能打开客户端。
3. **批量导入/导出账号档案**
   - 适用：换机或团队初始化。
   - 要求：导入时继续走脱敏 + 钥匙串流程，不落盘明文手机号。
4. **登录状态有效期提示**（未完成）
   - 现状：人工确认没有时间衰减，账号模型也没有确认时间字段。
   - 建议：先为 `Account` 增加 `lastConfirmedAt` 字段与 v7 迁移，再在界面展示「确认于 N 天前」，但不自动改写状态。

### 14.6 工程化（优先级：中）

1. **Developer ID 签名与公证、硬化运行时**，减少分发阻力。
2. **自动更新**（Sparkle 或自建）与版本迁移提示。
3. **UI 测试与集成测试**：当前 177 项均为 Core / AppState 单元测试；可补充快速切换小部件、切换流程、备份恢复、迁移的端到端测试。
4. **数据库迁移测试**：为 v1→v7 的每一跳准备 fixture，防止升级破坏老数据。
5. **可访问性与本地化**：补充 VoiceOver 标签、英文界面。

## 16. 术语表

| 术语 | 含义 |
|---|---|
| 账号档案 | 本机 SQLite 中的一条账号记录，不等于官方平台账号 |
| 脱敏手机号 | 形如 `138****1234`，保存在 SQLite |
| 手机号摘要 | 完整手机号的 SHA-256，用于查重 |
| 独立配置目录 / `user-data-dir` | TRAE 为每个账号分配的独立配置与会话目录 |
| 独立实例 | 使用某个账号 `user-data-dir` 启动的 TRAE 进程 |
| 等待核对 | 客户端已启动，但尚未在官方界面确认登录身份 |
| 已人工确认 | 用户在官方界面核对后，在本应用点击确认 |
| 已验证身份 | 通过官方 CLI 返回的身份信息，仅代表验证当时 |
| 确认冲突 | 多个 WorkBuddy 账号同时标记为已确认，逻辑上不可能同时成立 |
| 预计余额 | 最近一次录入余额减去基准之后采集到的任务消耗 |
| 未采集消耗 | 任务已记录，但日志中没有可解析的积分消耗 |
| 精确项目记录 | 由本应用发起并记录的打开事件 |
| 近似项目活动 | 由 TRAE `workspace.json` 修改时间推断的打开行为 |
| schema 版本 | SQLite `PRAGMA user_version`，当前为 7 |
